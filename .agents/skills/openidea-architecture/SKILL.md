# OpenIDEA Architecture & Data Flow

OpenIDEA is a native IDE inspired by IntelliJ IDEA, built with a **Rust backend** (33 workspace crates + a thin Tauri v2 desktop shell) and a **React 19 + TypeScript + CodeMirror 6 + Zustand** frontend.

## Architectural Principles

1. **Headless Backend (`ide-host`) vs. Desktop Glue (`src-tauri`)**:
   - Domain logic never lives in `src-tauri/`. `src-tauri` is strictly a windowing/IPC adapter wrapping `Arc<ide_host::Host>`.
   - `ide-host` is UI-toolkit agnostic: it powers both the local Tauri desktop app and the headless `openidea-server --stdio` binary used for SSH Remote Development.
   - Domain crates (`ide-*`) never depend on Tauri. They emit events via the `ide_core::EventSink` trait.
2. **Contribution-Driven Frontend (`src/workbench` vs. `src/features`)**:
   - `src/workbench/` and `src/editor/core/` never import feature modules (`src/features/*`).
   - Instead, features register UI and editor extensions during startup (`activateFeatures()` in `src/features/index.ts`) through registries in `src/workbench/contributions.ts`, `src/editor/api.ts`, and `src/platform/actions.ts`.
3. **Single Authoritative Document Model (`Documents` + `DocSync`)**:
   - Open files are stored in Rust as `ropey` ropes in `ide_workspace::Documents` and synchronized with CodeMirror 6 in the frontend via single-server OT (`src/editor/core/sync/DocSync.ts`).

## Codebase Map

### Backend (`crates/` & `src-tauri/`)

- **Core Primitives**:
  - `crates/ide-core`: Shared IDs (`DocId`, `RequestId`, `ServerId`, `TaskId`), settings schemas (`settings.rs`), `IdeError`, and the backend-to-UI event bus (`IdeEvent`, `EventSink`).
  - `crates/ide-text` & `crates/ide-vfs`: Rope buffers, UTF-8/UTF-16/line-col offset conversions, atomic file writes, encoding detection, and debounced filesystem watching (`Watcher`).
  - `crates/ide-language` & `crates/ide-syntax`: Loads the 60+ `languages/*.toml` definitions and manages incremental Tree-sitter parsing (`SyntaxCache`), syntax highlighting, folding, and structure outlines (`StructureService`).
- **Workspace, Indexing & Code Insight**:
  - `crates/ide-workspace`: Open document table (`Documents`), `DocumentObserver` trait, `LocalHistory`, `SettingsStore` (global + `.idea` project settings), and source/test/excluded root detection.
  - `crates/ide-index` & `crates/ide-search`: Persistent trigram/symbol index (`redb`), fuzzy matcher (`nucleo-matcher`), and ripgrep-backed (`grep-searcher`) Find in Files.
  - `crates/ide-lsp` & `crates/ide-analysis`: Language Server Protocol lifecycle (`LspManager`), multi-server routing, JDTLS/TypeScript/Angular bridges, virtual documents, and static inspections.
- **Execution & Tooling Crates**:
  - `crates/ide-run`, `crates/ide-dap`, `crates/ide-build`, `crates/ide-coverage`, `crates/ide-profiler`, `crates/ide-sdk`, `crates/ide-tools`: Process execution, Debug Adapter Protocol (`DebugManager`), Maven/Gradle/Cargo models, code coverage, flamegraphs, SDK detection, and managed tool/JDK downloads.
  - `crates/ide-vcs`, `crates/ide-github`, `crates/ide-terminal`, `crates/ide-db`, `crates/ide-http`, `crates/ide-notebook`, `crates/ide-agent`, `crates/ide-plugin`, `crates/ide-ssh`, `crates/ide-remote`, `crates/ide-docker`, `crates/ide-web`, `crates/ide-spell`, `crates/ide-clipboard`, `crates/ide-fonts`: Feature-specific domain crates.
- **Orchestrator & Shell**:
  - `crates/ide-host`: Defines `Host` (`lib.rs`), per-window `Project` (`project.rs`), shared command implementations (`ops/*.rs`), project trust (`trust.rs`), and the remote JSON-RPC server (`rpc.rs`, `bin/server.rs`).
  - `src-tauri`: Defines `AppState` (`state.rs`), Tauri `#[tauri::command]` wrappers (`commands/*.rs`), window/menu management, and the client side of remote development (`remote_dev.rs`).

> For the detailed crate dependency hierarchy and responsibilities, see [references/crate-map.md](./references/crate-map.md).

### Frontend (`src/`)

- `src/bindings.ts`: Auto-generated by `tauri-specta` (`pnpm gen:bindings`). **Never edit manually.**
- `src/platform/`:
  - `ipc.ts`: `call(commands.foo(...))` wrapper, `onIdeEvent()` subscriber, and `nextRequestId()`.
  - `actions.ts`, `context.ts`, `keymap.ts`: IntelliJ-style `ActionManager` (`registerAction`, `executeAction`) and `when` / `keyWhen` context expression evaluation.
  - `project.ts`: `useProject` Zustand store (current `project`, `settings`, `lightEdit`).
  - `tauriCore.ts` & `remote.ts`: Vite aliases `@tauri-apps/api/core` to `tauriCore.ts` so `invoke` can be transparently rerouted to `openidea-server` in remote windows.
- `src/ui/`: Design system primitives (`Tree`, `List`, `Dialog`, `Popup`, `Menu`, `Tabs`, `Splitter`, and `expui`/`openidea` icons).
- `src/workbench/`: The "Islands" shell (`Workbench.tsx`, `TitleBar.tsx`, `ToolWindows.tsx`, `EditorArea.tsx`, `StatusBar.tsx`) and extension registries (`contributions.ts`).
- `src/editor/`:
  - `api.ts`: Public contract for features to extend CodeMirror (`registerEditorContribution`, `scrollbarMarks`, `gutterLaneMarkers`, `codeLenses`, `registerSaveParticipant`, `whenSynced`).
  - `core/`: `EditorController` (`controller.ts`), `DocumentManager` (`model/document.ts`), `DocSync` (`sync/DocSync.ts`), and base CodeMirror setup (`cm/`).
  - `lsp/`, `navigation/`, `structure/`, `refactor/`: Editor intelligence layers.
- `src/features/*`: ~40 independent feature packages activated by `src/features/index.ts`.

## Core Data Flows

### 1. Boot & Window Lifecycle (`src/main.tsx` & `src-tauri/src/lib.rs`)
1. **Rust Setup**: `src-tauri/src/lib.rs` initializes logging, inherits the login shell PATH, spawns a background thread to warm up Tree-sitter grammars (`Syntax::new()`), creates `AppState` (which constructs `ide_host::Host`), and opens the main window.
2. **Webview Entry (`src/main.tsx`)**:
   - Checks `settingsWindowParent()`: if the window label is `settings-<parent>`, it renders `<SettingsWindow />` and activates only settings pages (`activateSettingsWindowFeatures`).
   - Otherwise, it calls `activateWorkbench()`, `activateFeatures()`, `installKeyboardDispatcher()`, and renders `<Workbench />`.

### 2. Project Open & File Watching (`crates/ide-host/src/project.rs`)
When `Host::open_project(window, root)` runs:
1. Canonicalizes `root`, verifies `.openidea/workspace.toml` (if any), and checks `TrustStore::trusted(&root)`.
2. Loads `SettingsStore` (merging global settings with `<root>/.idea` settings) and auto-detects source/test/excluded roots (`ide_workspace::roots::detect`).
3. Opens `LocalHistory` and `ProjectIndex` (`redb` in `local_data_dir/index/<fnv1a_key>`).
4. Configures `LspManager` hooks and registers `DocumentObserver`s on `Documents`:
   - `SyntaxObserver` $\rightarrow$ updates incremental Tree-sitter trees in `SyntaxCache`.
   - `LspObserver` $\rightarrow$ sends `didOpen`, `didChange`, `didSave`, `didClose` to running language servers.
   - `HistoryObserver` $\rightarrow$ records `"Saved"` snapshots in `LocalHistory`.
   - `DeployObserver` $\rightarrow$ uploads saved files to SFTP if auto-deploy is enabled and the project is trusted.
   - `KotlinBridge` $\rightarrow$ syncs Kotlin/Gradle classpaths.
5. Starts the debounced `ide_vfs::Watcher`. Disk changes update `ProjectIndex`, notify `LspManager` and `KotlinBridge`, reload clean open `Documents` (`on_disk_changed`), record external changes in `LocalHistory`, re-detect project/VCS roots if build files or `.git/HEAD` changed, and emit `IdeEvent::FsChanged` / `IdeEvent::VcsChanged`.

### 3. Document Synchronization (`DocSync` $\leftrightarrow$ `Documents`)
See [references/data-flows.md](./references/data-flows.md) for the complete state machine.
- **Local typing**: CodeMirror transactions feed into `DocSync.local(changes)` (`src/editor/core/sync/DocSync.ts`). Edits are buffered per animation frame and sent via `commands.docEdit(doc, baseVersion, changes)` (at most one request in flight per document).
- **Backend patches**: When Rust modifies a buffer (disk reload, `apply_workspace_edit`, formatting), `Documents` bumps the version and emits `IdeEvent::DocPatched { doc, baseVersion, version, changes }`. `DocSync.remote(patch)` transforms any in-flight/buffered local edits against the patch and dispatches the transformed delta into CodeMirror with the `remoteChange` annotation.
- **Position-dependent LSP calls**: Because LSP servers read the Rust backend's copy of the document, any frontend feature making an edit-sensitive LSP call (format, rename, code actions) **must** `await whenSynced(view)` (from `@/editor/api`) before invoking the backend command.

### 4. Validation & Verification Commands
- **Typecheck (TS)**: `pnpm typecheck`
- **Frontend Unit Tests**: `pnpm test` (Vitest)
- **Rust Tests**: `cargo test --workspace` (or `cargo test -p <crate>`)
- **Regenerate IPC Bindings**: `pnpm gen:bindings`
- **Lint & Format**: `pnpm lint` (`oxlint`) and `pnpm format:check` (`oxfmt`)
